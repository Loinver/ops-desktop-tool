## 3. 本轮收口实现

### 3.1 统一调度控制

- 新增 `ops-maintenance-window.json`，限制窗口最长 7 天、最远 30 天，并校验时间范围与原因长度。
- 自动调度器在窗口生效时跳过到期执行；人工运行保持可用。
- 新增自动化任务批量入口，动作限定为 `run`、`pause`、`resume`，每批最多 10 项，主进程重新读取任务、串行执行并在失败时停止。
- 任务中心增加安全选择、批量结果摘要和窄屏布局。

### 3.2 审计管理

- 审计状态升级为 v2，记录 `previousHash` 与 `integrityHash`。
- 旧版 v1 数据仅在明确版本迁移时建立完整性链；v2 链损坏、哈希缺失或 JSON 损坏会进入错误状态并拒绝覆盖。
- 查询支持有界分页、分类/状态筛选和失效游标报错。
- 清理必须由 Renderer 确认且明确指定分类，主进程再次强制校验。
- 导出按链顺序输出，并标注完整链或筛选子集的独立验证能力。
- Renderer 使用请求代次和筛选快照，避免旧请求覆盖新筛选，也固定确认时的清理范围。

### 3.3 Windows Node 指标

- Windows 通过 PowerShell `Get-CimInstance Win32_PerfFormattedData_PerfProc_Process` 与 `Win32_Process` 查询 CPU、工作集、创建时间和父 PID。
- 解析器支持单对象/数组 JSON、真实零值和部分采集失败。
- Windows `netstat` 兼容 TCP/UDP 的 IPv4/IPv6 标签；`tasklist` 不依赖固定表头行数。
- Node 历史和洞察只统计在线且 CPU/内存字段完整的样本，缺失值保持 `null`。

### 3.4 发布流水线

- `v*` Tag 构建先创建或恢复草稿 Release，各平台直接上传稳定命名资产和校验和片段。
- 汇总任务验证 macOS arm64/x64、Windows EXE/ZIP 和完整 `SHA256SUMS.txt` 后发布 Release。
- 普通 `main` Push 与 Pull Request 仅验证和构建，不产生发布资产。
- 当前仓库版本与 `v1.0.6` Tag 对齐。

## 4. 产品范围决策

以下能力不属于本机优先 v1 桌面版，也不作为本报告中的开发缺口：

- 远程 Agent、跨主机执行与多节点资产拓扑；
- 多用户协作、组织空间、RBAC、审批流和集中审计服务；
- 云账单聚合、团队 SLA、集中告警路由和服务端长期时序数据库；
- 无受控服务定义时的一键进程重启；应用坚持不把端口占用进程自动视为可安全重启的服务。

这些方向需要独立的服务端身份、设备信任、密钥托管、租户隔离和远程执行架构。若产品目标切换为团队控制面，应另立产品规格与威胁模型，不在本机 v1 上隐式扩展权限。

## 5. 安全边界

- 批量操作仅覆盖自动化健康检查，不提供批量杀进程、删除、恢复、发布、上传或任意命令执行。
- 维护窗口只延后自动调度，不删除任务，也不伪造失败。
- 进程终止、恢复、回滚、发布、外部网站打开等动作继续要求专用确认或 Runbook。
- 审计链用于本地篡改检测，不替代外部不可变日志服务。
- Renderer 不接收 Provider/SFTP 密钥、备份密码、原始模型回复或诊断原文。
