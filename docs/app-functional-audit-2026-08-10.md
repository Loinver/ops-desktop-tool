# Ops Desktop 功能闭环验收报告（2026-08-10）

## 1. 结论

截至 2026-08-10，v1.0.7 工作树已经完成本机优先 v1 的代码收口，并通过本地自动化门禁；当前结论是“本地可发布候选”，不是“已完成外部发布”。应用可在单台用户设备上完成：状态发现、风险汇总、任务执行、结果复检、事件恢复、操作留痕、诊断导出、备份恢复和版本发布。AI 对话与生图已具备安全失败边界，但真实第三方 Provider、真实 SFTP 服务器和跨平台安装包仍需在发布前做外部验收。

本报告是当前开发状态的唯一有效审计基线。`app-functional-audit-2026-08-07.md` 仅作为历史快照索引。

## 3. 本轮收口实现

### 3.1 统一调度控制

- 新增 `ops-maintenance-window.json`，限制窗口最长 7 天、最远 30 天，并校验时间范围与原因长度。
- 自动调度器在窗口生效时跳过到期执行；人工运行保持可用。
- 新增自动化任务批量入口，动作限定为 `run`、`pause`、`resume`，每批最多 10 项，主进程重新读取任务、串行执行并在失败时停止。
- 任务中心增加安全选择、批量结果摘要和窄屏布局。

### 3.2 审计管理

- 审计状态升级为 v2，记录 `previousHash` 与 `integrityHash`。
- 旧版 v1 数据仅在明确版本迁移时建立完整性链；v2 链损坏、哈希缺失或 JSON 损坏会进入错误状态并拒绝覆盖。
- 查询支持有界分页、分类/状态筛选和失效游标报错。
- 清理必须由 Renderer 确认且明确指定分类，主进程再次强制校验。
- 导出按链顺序输出，并标注完整链或筛选子集的独立验证能力。
- Renderer 使用请求代次和筛选快照，避免旧请求覆盖新筛选，也固定确认时的清理范围。

### 3.3 Windows Node 指标

- Windows 通过 PowerShell `Get-CimInstance Win32_PerfFormattedData_PerfProc_Process` 与 `Win32_Process` 查询 CPU、工作集、创建时间和父 PID。
- 解析器支持单对象/数组 JSON、真实零值和部分采集失败。
- Windows `netstat` 兼容 TCP/UDP 的 IPv4/IPv6 标签；`tasklist` 不依赖固定表头行数。
- Node 历史和洞察只统计在线且 CPU/内存字段完整的样本，缺失值保持 `null`。

### 3.4 发布流水线

- `v*` Tag 构建先创建或恢复草稿 Release，各平台直接上传稳定命名资产和校验和片段。
- 汇总任务验证 macOS arm64/x64、Windows EXE/ZIP 和完整 `SHA256SUMS.txt` 后发布 Release。
- 普通 `main` Push 与 Pull Request 仅验证和构建，不产生发布资产。
- 当前工作树版本为 `1.0.7`；`HEAD` 仍是 `v1.0.6`，v1.0.7 尚未创建 Tag、构建远端 Release 或推送。

### 3.5 v1.0.7 本地候选验收（2026-08-10）

- `package.json` 版本已为 `1.0.7`，变更覆盖 AI 生图资源隔离、远程资源 SSRF 防护、剪贴板配额和 SFTP 主机指纹校验。
- `pnpm check` 已通过：269 个 Node 测试、40 个 Renderer 测试、7 个 Electron E2E；Prettier、ESLint、IPC 边界检查和 Vite 生产构建均通过。
- 真实 Electron 路由巡检覆盖 18 个路由、1400×900 与 960×640 两种窗口，共 36 次加载；未发现页面错误、请求失败、控制台错误、页面级横向溢出、嵌套纵向滚动或“待开发/敬请期待/coming soon”占位文案。
- 任务中心、模型测试和 Node 服务在窄窗口下出现的几何裁剪来自显式横向滚动表格或筛选条容器，不属于页面级内容截断；仍需在正式 UI 验收中确认触控板/滚轮能够进入局部横向滚动容器。

## 4. 产品范围决策

以下能力不属于本机优先 v1 桌面版，也不作为本报告中的开发缺口：

- 远程 Agent、跨主机执行与多节点资产拓扑；
- 多用户协作、组织空间、RBAC、审批流和集中审计服务；
- 云账单聚合、团队 SLA、集中告警路由和服务端长期时序数据库；
- 无受控服务定义时的一键进程重启；应用坚持不把端口占用进程自动视为可安全重启的服务。

这些方向需要独立的服务端身份、设备信任、密钥托管、租户隔离和远程执行架构。若产品目标切换为团队控制面，应另立产品规格与威胁模型，不在本机 v1 上隐式扩展权限。

## 5. 安全边界

- 批量操作仅覆盖自动化健康检查，不提供批量杀进程、删除、恢复、发布、上传或任意命令执行。
- 维护窗口只延后自动调度，不删除任务，也不伪造失败。
- 进程终止、恢复、回滚、发布、外部网站打开等动作继续要求专用确认或 Runbook。
- 审计链用于本地篡改检测，不替代外部不可变日志服务。
- Renderer 不接收 Provider/SFTP 密钥、备份密码、原始模型回复或诊断原文。

## 6. 验证标准

收口验收命令：

```bash
pnpm check
git diff --check
```

`pnpm check` 覆盖 Prettier、ESLint、Node 测试、Renderer 测试、Electron E2E 与 Vite 构建。新增回归测试覆盖审计完整性与管理、Windows 指标、Node 指标可用性、维护窗口、自动化批量操作和任务中心交互。

## 7. 状态声明

本机优先 v1 范围内没有发现源码级占位功能或未接线的主路由；当前仍有四类发布前外部验收项，见 3.5。v1.0.7 适合作为 Release Candidate 继续验证，不应在未完成真实 Provider、真实 SFTP、CI 资产和 macOS 签名验收前直接宣称“生产发布完成”。

## 9. AI 效率功能路线图

### P0：下一版本优先完成

- **流式 AI 对话 + 取消/重试**：响应首字节即可展示，用户可中断 60 秒长请求；失败时保留原问题和知识证据，避免重复编辑。
- **对话管理**：会话列表、重命名、搜索、Markdown/JSON 导出；当前已先加入安全有界的本机暂存和 Markdown 导出。
- **上下文附件**：允许用户从日志分析、事件详情、发布预检和知识库选择证据片段，统一脱敏、限长并显示来源。
- **用量与费用保护**：按 Provider/模型统计请求次数、输入输出 Token（若上游提供）、估算费用和每日/每月预算；超过预算只允许手动确认。
- **AI 行动审批**：任何发布、删除、回滚、外部打开或进程终止都先生成可读计划，显示影响对象和回滚点，用户确认后逐步执行并写入审计。

### P1：直接提升运维效率

- **事件 Copilot**：把事件、Node 指标、日志片段、最近发布和 Runbook 合并成时间线，输出事实/推测/建议/下一步验证。
- **发布风险摘要**：发布前自动比较变更、忽略规则、目标环境和历史失败原因，生成风险清单与发布后验证清单。
- **知识库升级**：目录导入、增量索引、语义检索与关键词检索混合排序，所有引用显示文档、行号和更新时间。
- **故障复盘生成器**：从事件时间线生成复盘草稿、影响范围、根因假设、修复动作和预防项，用户确认后保存为知识文档。
- **运维报告/值班摘要**：按时间范围生成可导出的日报、周报和未闭环事项清单，敏感信息继续脱敏。

### P2：需要更大架构投入

- 多模态故障证据（截图、拓扑、监控图表、图片理解）；
- 跨主机 Agent、团队协作、RBAC、审批流和集中审计；
- 受控工作流编排、定时 AI 总结与外部通知渠道；
- 团队级模型路由、质量基准、成本配额和策略中心。

P2 不应通过 Renderer 直接增加 shell、远程执行或凭证访问权限，应在独立的服务端身份、设备信任和审计模型完成后再规划。
